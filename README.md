# shikaku-score（erabiyori.jp）— 合格ラインとの距離

**リポジトリ名は shikaku-score だが、公開先は erabiyori.jp。**

得点を入れると、合格ラインまでの距離と判定が出る。宅建と行政書士。

- 公開先: https://erabiyori.jp
- 配信: GitHub Pages（`dist/CNAME` は `SITE_DOMAIN` から作る）
- **入力した内容はどこにも送信されない。** ブラウザの中だけで動く

## スタディングと、どこを変えたか

スタディングのAI実力スコアは「**繰り返し学習した場合**にスコアが高くなる」と
公式に明記されている。つまり「できるか」と「やったか」が1つの数字に混ざっていて、
どちらがどれだけ効いているか利用者に見えない。

繰り返した人が受かりやすいのは事実だろうが、それは相関であって因果ではない。
しかも**教材を使うほど数字が上がる**のは、教材提供者に都合がよい設計でもある。

**ここでは繰り返しを一切加点しない。** 入れた得点だけで判定する。

## 本試験での偏差値は出さない

出すには受験者の得点分布が要る。**宅建も行政書士も、得点分布は公表されていない。**
合格率と合格点から逆算しようにも、式が1本で未知数が2つあり解けない。

**根拠のない偏差値は嘘と同じ**なので出さない。代わりに、公表された合格点だけで
言えることを出す。判定の根拠は「過去◯年のうち何年で合格ラインを超えたか」で、
1行で説明できる。

## 資格で合格基準の性質が違う

| | 宅建 | 行政書士 |
|---|---|---|
| 基準 | **相対**（上位◯%） | **絶対**（180点固定） |
| 合格点 | 毎年動く（31〜38点） | 180点 |
| 足切り | なし | **あり**（法令等122・基礎知識24） |
| 見せ方 | 過去10年で何年合格したか | 180点まであと何点か＋足切り |

**同じ見せ方はできない。** 切り替えられるようにしてある。

**足切りは総合点に埋めない。** 総合が足りていても、基礎知識が24点未満なら不合格。
総合点の内側に隠すと気づけないので、E判定にして理由を書く。

## 模試の分布（行政書士のみ）

実際に受験した模試の得点分布を持っているので、その中での偏差値と順位を出す。

    令和5年の模試 / 104人 / 平均162.3点 / 標準偏差37.1点

**ただしこの母集団は本試験の受験者ではない。** 181点以上が27.9%で、
本試験の合格率14.54%の約2倍。本気の受験生だけが受けている偏った集団なので、
「本試験での位置」として使ってはいけない。画面にもそう書いてある。

**分母にも注意。** この模試は記述式込みの300点満点。
スタディングのAI実力スコアは記述式を除いた240点満点なので、
そのまま入れると意味のない偏差値が出る。入力欄の下に常時警告を出している。

## 数値の確認

`config/exams.json` の `verified` が `false` のあいだは、画面に
「まだ公式で確かめていない」と表示される。**推測で数値を書かない**方針。

    宅建      一般財団法人 不動産適正取引推進機構
    行政書士   一般財団法人 行政書士試験研究センター

受験者数はアフィリエイトサイト経由の数字なので、公式の公表資料で
差し替えてから `verified` を `true` にすること。

## 配信

**Vercel から配信する。** `vercel.json` にビルドコマンドと出力先を書いてある。

    buildCommand      node scripts/build_site.mjs
    outputDirectory   dist

セットアップは一度だけ。Vercelでこのリポジトリを Import し、
Project Settings → Domains に `erabiyori.jp` を追加する。
**その画面に、いまのDNSと、何を書き換えればいいかが出る。**

`SITE_DOMAIN` は設定しなくてよい。あれは GitHub Pages 用に `dist/CNAME` を
作るための変数で、Vercelは CNAME ファイルを見ない。

GitHub Pages は使っていない。`.github/workflows/deploy.yml` は手動実行だけ
残してある。戻す場合の手順はそのファイルの先頭に書いた。

## 会員制

**環境変数が入っていないあいだ、会員機能は画面に出ない。** 得点判定・スコアの推移・
模試分布は、これまでどおり動く。段階的に入れられるようにしてある。

### 何が無料で、何が有料か

| | 無料 | 有料 |
|---|---|---|
| 合格点との差・足切り判定・ABCDE | ○ | ○ |
| 模試分布での偏差値・順位・平均との差 | ○ | ○ |
| スコアの推移（端末内） | ○ | ○ |
| 会員平均との差 | — | ○ |
| 端末をまたぐ記録の引き継ぎ | — | ○ |

**無料側は削らない。** いま出しているものを有料に引き上げると既存の利用者を
失ううえ、無料で使える範囲が狭いと会員平均の元データが育たない。

### 会員平均を出す条件

**提供者が30人に満たないあいだは出さない。** 少人数の自己申告平均は、数人の
増減で大きく動くうえ検証できない。「根拠のない偏差値は嘘と同じ」という
このサイトの方針は、自分が出す数字にも同じように効かせる。

閾値は `api/average.mjs` と SQL 関数 `member_average` の両方で止めてある。
画面側の実装ミスで少人数の平均が漏れ出す事故を防ぐため、二重にしてある。

出すときは必ず「**会員が自己申告した得点の平均**であり、本試験の受験者全体の
平均ではない」と併記する。

### 得点の送信はオプトイン

サーバに送るのは、画面で「会員平均に、自分の得点を提供する」をオンにしたときだけ。
既定は `false`。オフのまま保存された行は集計に入らない（`scores.shared`）。

トップの文言は「どこにも送信されません」から「**提供をオンにしない限り
送信されません**」に変える必要がある。既存の利用者との約束を破らないため。

### つなぎ方

1. Supabase でプロジェクトを作り、SQL Editor で `supabase/schema.sql` を実行する
2. Stripe でサブスクリプションの price を1つ作る
3. Stripe の Webhook を `https://<ドメイン>/api/stripe-webhook` に向ける。
   送るイベントは `checkout.session.completed` と
   `customer.subscription.created` / `updated` / `deleted`
4. Vercel の Environment Variables に `.env.example` の値を入れる

`SUPABASE_SERVICE_ROLE_KEY` は**サーバ専用**。ブラウザに出したら全行が
読み書きできてしまう。`api/` 配下からしか読み込まない。

### 持たないもの

氏名・住所・生年月日・電話番号は持たない。**持てば漏れる。**
必要なのは本人を指す id と得点だけ。

### 署名の検証

Stripe の Webhook は署名を必ず検証する。検証しないと、誰でも「支払った」と
偽の通知を送って有料会員になれてしまう。検証の動作確認は次で走る。

    node scripts/test-webhook-signature.mjs

改ざん・別シークレット・古い署名・ヘッダ欠落を、それぞれ弾くことを確かめている。

### 有料にすると要るもの（コードの外）

特定商取引法に基づく表記、利用規約、プライバシーポリシーの改定、消費税の扱い。
**これらが揃うまで課金は開始しない。**

## 使い方

```bash
node scripts/build_site.mjs
SITE_DOMAIN=erabiyori.jp node scripts/build_site.mjs
```
